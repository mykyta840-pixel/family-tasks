# Семья — задания, баллы и награды

Приложение для всей семьи. Родитель создаёт задания, ребёнок нажимает «Выполнено», родитель подтверждает, и ребёнок получает баллы. Баллы можно обменять на награды. Работает как обычный сайт и как приложение на главном экране телефона.

Технологии: React + TypeScript + Vite, Tailwind CSS, Supabase (вход, база данных, обновления в реальном времени).

---

## Что понадобится

- Бесплатный аккаунт на [supabase.com](https://supabase.com) (база данных и вход)
- Бесплатный аккаунт на [github.com](https://github.com) и на [netlify.com](https://netlify.com) (чтобы приложение было доступно с телефонов)
- Для запуска на компьютере: [Node.js](https://nodejs.org) (кнопка LTS)

---

## Шаг 1. База данных (Supabase)

1. На supabase.com создайте проект (регион Европа). Придумайте пароль базы и сохраните его.
2. Подтверждение почты отключите: **Authentication → Sign In / Providers → Email**, выключить «Confirm email». Так дети смогут входить сразу после регистрации.
3. Откройте **SQL Editor** и по очереди выполните пять файлов из папки `supabase/manual/`, строго по порядку:
   `01_tables.sql`, `02_rls.sql`, `03_triggers.sql`, `04_actions.sql`, `05_final.sql`.
   Содержимое файла копируйте целиком, вставляйте в редактор и нажимайте **Run**.
   Если Supabase покажет окно про «потенциальную проблему RLS», выберите **«Запуск без RLS»** (это нормально, защита включается в этих же файлах).
   Те же команды одним файлом лежат в `supabase/migrations/001_init.sql`, использовать нужно что-то одно.
4. Откройте **Project Settings → API** и скопируйте два значения: **Project URL** и **публичный ключ** (`anon` / `publishable`). Секретный ключ (`service_role`) никуда вставлять нельзя.

## Шаг 2. Ключи в приложении

1. Скопируйте файл `.env.example` в новый файл `.env`.
2. Вставьте свои значения:
   ```
   VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
   VITE_SUPABASE_ANON_KEY=ваш-публичный-ключ
   ```
3. Файл `.env` не попадает в GitHub (он в `.gitignore`), и это правильно.

## Шаг 3. Запуск на компьютере

В терминале, в папке проекта:

```
npm install
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:5173). Команда `dev` открывает приложение и для телефонов в той же Wi-Fi сети: используйте адрес «Network», который покажет терминал.

Если вместо входа вы видите «Нужно подключить Supabase», значит `.env` не заполнен или после его правки не перезапущен `npm run dev`.

## Шаг 4. Выложить в интернет (Netlify)

1. Загрузите проект на GitHub (новый репозиторий, папка проекта целиком; `.env` и `node_modules` туда не попадут сами).
2. На netlify.com: **Add new site → Import from Git**, выберите репозиторий. Настройки подтянутся из `netlify.toml` (команда `npm run build`, папка `dist`).
3. Откройте **Site configuration → Environment variables** и добавьте те же две переменные: `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
4. Нажмите **Deploy**. Через пару минут появится ссылка вида `https://что-то.netlify.app`.
5. Если ключи добавлены после первой сборки, запустите **Deploys → Trigger deploy → Clear cache and deploy site**.

После этого каждое изменение, отправленное на GitHub, публикуется автоматически.

## Шаг 5. Первый запуск в семье

1. Первый родитель: зарегистрироваться → «Создать семью».
2. На экране «Семья» создать **код приглашения** (10 символов, одноразовый, действует 7 дней).
3. Второй родитель и дети регистрируются со своей почтой и вводят код при входе в семью.
4. Родитель создаёт задания и награды, ребёнок отмечает выполнение, родитель подтверждает.

## Установка на телефон

- **iPhone (Safari):** кнопка «Поделиться» → «На экран Домой».
- **Android (Chrome):** меню ⋮ → «Установить приложение» / «Добавить на главный экран».

## Проверка кода

```
npm test           тесты (даты, фильтры заданий, тексты ошибок, уведомления)
npm run typecheck  проверка типов TypeScript
npm run build      полная сборка, как её делает Netlify
```

Тесты проверяют логику, которая не требует интернета и Supabase. Работу экранов и базы они не заменяют: после первой сборки пройдите руками чек-лист ниже.

### Ручной чек-лист (на двух телефонах)

1. Родитель создаёт семью и код. Ребёнок входит по коду.
2. Родитель создаёт задание для ребёнка. У ребёнка оно появляется само, без обновления страницы.
3. Ребёнок нажимает «Выполнено». У родителя появляется уведомление.
4. Родитель подтверждает. Баллы у ребёнка растут, в «Истории» есть запись.
5. Родитель создаёт награду. Ребёнок просит выдать, родитель выдаёт, баллы списываются.
6. Задание с прошедшим сроком получает статус «Просрочено» в течение минуты.
7. Выключите интернет: появляется баннер «нет связи», кнопки блокируются. После включения данные обновляются сами.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| «Нужно подключить Supabase» | Заполнить `.env` (или переменные в Netlify) и перезапустить / пересобрать |
| «Код не подошёл» | Код одноразовый и живёт 7 дней: создать новый на экране «Семья» |
| Ошибка при выполнении SQL | Выполнять файлы строго по порядку 01 → 05, копировать целиком, при предупреждении RLS выбирать «Запуск без RLS» |
| Белый экран или «Что-то пошло не так» | Нажать «Обновить». Если повторяется, прислать текст ошибки из консоли браузера (F12) |
| На Netlify открывается, но входа нет | Проверить две переменные окружения и пересобрать сайт |
| Новая версия не появляется на телефоне | Закрыть приложение полностью и открыть снова (приложение обновляется само при следующем запуске) |

## Структура проекта

```
src/pages/        экраны (вход, задания, награды, история, профиль, семья)
src/components/   карточки, окна, меню, экран ошибки
src/data/         общие данные семьи и уведомления (realtime)
src/lib/          чистая логика (задания, награды, даты) и тесты в __tests__
supabase/manual/  SQL для Supabase по частям
PROJECT_CONTEXT.txt  заметки по этапам разработки
```

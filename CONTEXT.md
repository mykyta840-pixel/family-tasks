## ЭТАП C: что сделано (пункт 7)

### Решения (согласованы с Никитой)
- Ребёнок входит **анонимно** (`signInAnonymously`) по коду приглашения + имя, без почты и пароля. Минус анонимного входа: если очистить данные браузера/переустановить приложение, сессия теряется. Поэтому добавлен **код возврата**: родитель в профиле ребёнка нажимает «Выдать код возврата» (`RET-XXXXXX`, одноразовый, 48 часов, новый код отменяет прежний), ребёнок на новом устройстве вводит его на том же экране «У меня есть код приглашения» и **все данные профиля переходят к его новому анонимному входу**.
- Второй родитель по коду: имя + почта + пароль (`signUp`, затем `join_with_code`). Первый родитель без кода: «Создать новую семью» (как раньше: регистрация, затем `create_family` в `Onboarding`).
- Формат кода приглашения `FAM-XXXXX` (алфавит без 0/O/1/I/L, 31 символ). Старые коды из 10 символов работают (поиск идёт по `replace(code,'-','') = нормализованный ввод`).

### SQL (supabase/manual/11a, 11b, 11c = migrations/007_join_by_code.sql)
- 11a: таблицы `code_attempts` (журнал неверных попыток) и `child_return_codes` (RLS включён, прав у клиента нет), `_rand_code(int)` (внутренняя), `create_family` (теперь отказывает анонимному входу: `not_allowed`), `create_invite` (формат FAM-XXXXX).
